# Reuse Matrix

## Decision rules

This matrix is current to **2026-09-12** and records a bounded upstream snapshot. “Recent” means evidence visible at the cutoff; it is not a warranty. Commit identifiers link to the inspected upstream history. GitHub's detected SPDX field was checked against the repository license text when it returned `NOASSERTION`.

Disposition meanings:

- **ADOPT** — a candidate dependency for a later implementation gate, pinned and reviewed before use.
- **REFERENCE** — learn from public architecture, tests, APIs, and failure history; do not copy code unless a new file-level license review approves it.
- **FORK** — maintain a derivative and accept its upstream license obligations. No surveyed project presently justifies this cost.
- **REJECT** — do not use as a dependency, derivative, or product control for this project.

No dependency was added, no upstream project was cloned or executed, and no upstream code was copied in Research Gate 0.

## License compatibility summary

| Upstream license | Can it be used while preserving this repository's PolyForm terms? | Required posture |
| --- | --- | --- |
| MIT / ISC | Generally yes for a dependency or copied portion, subject to copyright/license preservation | Retain upstream copyright and full permission text; inventory exact files/versions |
| Apache-2.0 | Generally yes, but patent, license, changed-file, attribution, and NOTICE duties must be preserved | Retain license and applicable NOTICE; mark changes; inventory patents/notices |
| MPL-2.0 | Yes as a larger work only if MPL-covered files and modifications remain available under MPL and recipients' MPL rights are not restricted | Keep package/files separable; preserve MPL and source offer; do not relabel upstream files as PolyForm-only |
| GPL-3.0 / GPL-3.0-or-later | Not suitable for copied/derived code distributed only under a noncommercial restriction; GPL forbids further restrictions | Do not copy, translate, fork, link, or bundle as a combined derivative under PolyForm-only terms; clean-room reference only |
| AGPL-3.0 | Same incompatibility concern as GPL, plus network-interaction source obligations | Do not copy/derive product code; use an independently deployed pinned Canvas instance only as a later test system after review |

This is a conservative engineering disposition, not legal advice. “Clean room” here means requirements and externally observable behavior are documented from official specifications and tests, while implementation authors do not copy protected expression from incompatible projects.

## Security-policy interpretation

A present `SECURITY.md` is a positive reporting signal, not proof of secure code. An absent file is not proof that no private channel exists; it means no repository-local policy was located in the inspected default-branch tree. Likewise, recent commits/releases do not prove that a project is suitable for this product. Permission scope, architecture, reproducibility, response history, transitive dependencies, and fit for purpose remain separate checks.

## High-risk and non-reuse boundary

Projects or products whose primary marketing includes quiz answers, proctoring bypass, hiding tab switches, suppressing focus/activity records, stealth, or fabricating clean logs are not reuse candidates. This includes the product/script classes documented in [canvas-tools-telemetry-and-network-controls.md](canvas-tools-telemetry-and-network-controls.md). Direct links and implementation details are intentionally omitted here. They must not be installed, run, copied, translated, forked, or used as design templates.
